Root Cargo.toml changes needed for `siar-emergency-service`
=============================================================

This is a brand-new crate, so it needs two additions to your root
`Cargo.toml`:

1. In `[workspace] members = [...]`, add (placed next to
   `siar-emergency`):

    "crates/siar-emergency-service",

2. In `[workspace.dependencies]`, add:

    siar-emergency-service = { path = "crates/siar-emergency-service" }

Note on `workspace-hack`:
This workspace uses `cargo-hakari` via the `workspace-hack` crate.
`crates/siar-emergency-service/Cargo.toml` includes:

    workspace-hack = { version = "0.1", path = "../../workspace-hack" }

Also note that `crates/siar-emergency` was updated with the new
`report_status` module (`ReportStatus`/`ReportEvent`/`InvalidReportTransition`)
that provides the decide state machine layer for emergency reports.

After these additions are in place:
- `cargo check -p siar-emergency-service`
- `cargo test -p siar-emergency-service`
- `cargo clippy -p siar-emergency -p siar-emergency-service -- -D warnings`
- `cargo hakari verify`

all succeed cleanly.
